# CMake build for the `scicos_blocks` module — Batch C (Fortran runtime,
# variant pair) on the shared scilab_module() helper (cmake/ScilabModule.cmake);
# built from the top-level scilab/CMakeLists.txt driver. HYBRID COEXISTENCE:
# this file is invisible to automake; the autotools scicos_blocks is always
# recoverable with `make -C modules/scicos_blocks`.
#
# VARIANT PAIR sharing ONE algo lib: automake folds the SAME
# libsciscicos_blocks-algo.la (233 C blocks + 2 C++ blocks + 57 Fortran blocks
# + 3 non-block sources) into BOTH pkglib dylibs — main adds the JNI helpers
# (HelpersJNI + AfficheBlock), `-cli` adds HelpersCLI instead. The -cli call
# consumes the main call's OBJECT lib via
# $<TARGET_OBJECTS:sciscicos_blocks-algo> — object-for-object what libtool
# linked, no double compile. Feeds Batch E (scicos/xcos link these targets).
#
# LINKING CLASS (modules/Makefile.am): main = ENGINE_LIBS_DYNAMIC_LOAD; -cli
# appears in NO aggregate link list (it is linked by libsciscicos-cli) -> no
# CLASS keyword.
#
# PARITY CONTRACT (arbitrated by build-parity/):
#   libsciscicos_blocks.2027.dylib      exports 398
#   libsciscicos_blocks-cli.2027.dylib  exports 387
#   both:  deps /opt/homebrew/opt/gcc/lib/gcc/current/libgfortran.5.dylib
#          + libquadmath.0 + /usr/lib/libc++.1.dylib + /usr/lib/libSystem.B.dylib
#
# EXTERNAL DEPS: only $(RT_LIB) (configured EMPTY) + $(FLIBS) — LANG Fortran
# rides the runtime in automatically (the interpolation-exemplar pattern).
#
# includes/blocks.h is an autotools BUILT source (GenBlocks.sh) — present in
# the configured tree this build requires; not regenerated here.
# EXTRA_INCLUDES = the algo CPPFLAGS' module set + HDF5_CFLAGS; the main call
# appends its JNI dirs (src/jni, commons/src/jni, jvm, JDK) exactly as
# libsciscicos_blocks_la_CPPFLAGS does. The shared algo objects compile with
# the MAIN call's include set (= algo's + the JNI extras appended) — the extras
# shadow nothing, same preprocessor result as the autotools algo compile.
